Project Case Study — FiveM / QBCore

Police Dispatch

A custom police faction script for a FiveM roleplay server, built from scratch on QBCore — replacing the default police job. Features a duty system, an emergency call dispatch with claim logic, and a menu-driven UI. Written entirely in Lua with client-server architecture and ox_lib.

Features

A complete dispatch workflow — from a civilian's 911 call to an officer closing the case.

Duty System

Officers toggle on/off duty at any police station. Job verification runs server-side — only players with the police job can go on duty.

Emergency Calls

Civilians trigger a 911 call with a message and their live location. Only on-duty officers receive the alert — filtered server-side by job and duty status.

Call Claiming

An officer claims a call from the menu. Once claimed, it disappears from everyone else's list — no two officers on the same call.

One Call at a Time

An officer can't claim a second call while one is active. Business rules are enforced on the server, never trusted from the client.

Blip & Route

Claiming a call places a waypoint and route to the caller's location, sent only to the officer who claimed it.

Resolve

Marking a call resolved removes it, clears the blip, and frees the officer to take the next one — closing the dispatch loop.

Architecture

Client-server split — the server is the single source of truth for all call state. The client never decides anything that matters.

Client

Interaction & UI

Markers, TextUI, and the call menu. Sends requests to the server (go on duty, create/claim/resolve a call) and renders what the server sends back. Holds no authoritative state.

Server

Call State & Rules

Owns the list of calls, each with a status and claimedBy field. Enforces every rule: job checks, claim availability, one-call limit, resolve.

Bridge

Events & Callbacks

Client-to-server events for actions, server-to-client events for notifications, and an ox_lib callback that returns each officer's available and active calls.

Framework

QBCore + ox_lib

QBCore provides the job and duty backend (SetJobDuty, GetQBPlayers). ox_lib provides notifications, context menus, and callbacks.

Code Highlights

A few interesting implementation details from the codebase.

Broadcast to a filtered group — only on-duty police receive the call:

local players = QBCore.Functions.GetQBPlayers()
for _, targetPlayer in pairs(players) do
    local job = targetPlayer.PlayerData.job
    if job.name == Config.JobName and job.onduty then
        TriggerClientEvent('ox_lib:notify', targetPlayer.PlayerData.source, {
            title = 'Apel Nou', description = message, type = 'inform'
        })
    end
end

Claim logic — server enforces both rules before granting the call:

-- rule 1: the call must still be available
if not call or call.status ~= 'nou' then -- taken already
    notify(src, 'Apel indisponibil') return
end

-- rule 2: the officer can't already have an active call
for id, c in pairs(calls) do
    if c.claimedBy == src and c.status == 'activ' then
        notify(src, 'Ai deja un apel activ') return
    end
end

-- both rules passed: claim it
call.status = 'activ'
call.claimedBy = src

Duty toggle — server verifies the job and flips duty in QBCore:

if Player.PlayerData.job.name ~= Config.JobName then
    notify(src, 'Nu faci parte din factiune') return
end
local newDuty = not Player.PlayerData.job.onduty
Player.Functions.SetJobDuty(newDuty) -- real QBCore state
