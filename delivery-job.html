Project Case Study — FiveM / QBCore

Delivery Job

A QBCore delivery job for a FiveM roleplay server. Players pick up a vehicle, complete a shift of six deliveries to random locations, and get paid — with real in-game money handled server-side, a progress circle with animations, and a return-the-vehicle finale.

Features

A full delivery shift, from pickup to payout.

Vehicle Spawn

Starting the job spawns a delivery vehicle at a fixed spot, hands the player the keys (unlocked), and puts them in the driver's seat.

Random Routes

Each delivery targets a random point from a list, with a guard that never picks the same location twice in a row.

Progress & Animation

Dropping off a package plays an ox_lib progress circle with a hand-over animation, cancellable with ESC.

Tiered Payment

Money per delivery plus a performance bonus at the end of the shift. Amounts are rolled on the server — the client only signals completion.

Return the Vehicle

After six deliveries, a route back to the depot appears. Returning the vehicle deletes it and pays the bonus.

Blips & Markers

A permanent job blip, plus a routed blip to each delivery target that is recreated on every new stop.

Architecture

A client-side state machine drives the shift; the server owns anything involving money.

Client

State Machine

Three states — idle, delivering, returning — drive a single loop that handles markers, distance checks, and interaction.

Server

Payments

Rolls the reward with math.random and calls AddMoney. The amount is never sent from the client — a security boundary against cheating.

Bridge

Events

A single parameterized event handles both per-delivery pay and the final bonus, distinguished by a boolean — keeping the code DRY.

Framework

QBCore + ox_lib

QBCore for money and vehicle keys, ox_lib for the progress circle and notifications.

Code Highlights

A few interesting implementation details.

Random target that never repeats the previous one — using a repeat-until loop:

local function getRandomPoint(avoid)
    local point
    repeat
        point = deliveryPoints[math.random(#deliveryPoints)]
    until point ~= avoid -- keep rolling until it's different
    return point
end

Reward rolled server-side — the client only says "done", never how much:

RegisterNetEvent('delivery:complete', function(isFinal)
    local Player = QBCore.Functions.GetPlayer(source)
    if not Player then return end
    local reward
    if isFinal then
        reward = math.random(1050, 1500) -- end-of-shift bonus
    else
        reward = math.random(350, 550) -- per delivery
    end
    Player.Functions.AddMoney('cash', reward)
end)

Progress circle with a hand-over animation on drop-off:

if lib.progressCircle({
    duration = 5000, label = 'Se livreaza...',
    canCancel = true,
    disable = { move = true, combat = true },
    anim = { dict = 'mp_common', clip = 'givetake1_a' }
}) then
    -- delivery completed
end
